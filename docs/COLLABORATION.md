# Codex 与 Claude Code 协作方案

## 工作台

GitHub 保存共同事实，分支保存改动，PR 保存审查证据，任务队列保存下一步。
两个产品不共享聊天记忆；PROJECT.md 不是自动执行器。入口为 AGENTS.md，CLAUDE.md 引用它。
不反复把所有旧聊天发给代理。每次给任务 ID、基准提交、相关文档、验收和限定范围。

## 第一阶段 现在可用的云端接力

1. 将准备分支合并或明确选为云端任务基准；两个工具都连接此仓库。连接 ChatGPT 的 GitHub 不自动等于 Claude 或 Codex 云环境已配置。
2. JOEdan 作为临时协调者，在默认分支任务表或关联 Issue 中指定任务负责人、独立分支和基准 SHA。
3. 例如 Claude 实现 T03，Codex 独立审查最终 SHA；也可以反过来，角色不代表模型能力排名。
4. 实现者运行针对性测试，提交 draft PR，更新交接信息；审查者先复现，再报告具体阻塞缺陷。
5. 作者最多做两轮修复；仍失败就保留复现与阻塞说明。由负责人决定集成。
6. 用户返回时看 PR、检查结果和待确认业务问题，不需要重读长对话。

云端已启动任务可以后台运行，是否可用及额度以账号实际环境为准。持续发现新任务、跨产品自动唤醒和合并属于下一阶段能力。

## 任务状态与所有权

`queued -> ready -> in_progress -> review -> done`，遇依赖或业务问题转 `blocked`。
任务必须有目标、允许改动范围、依赖、验收 ID 和负责人。认领由一个协调者串行处理，不能靠两个代理各自在分支上改状态来抢锁。
租约到期先确认原运行已结束；未结束不能把同一任务派给另一写入者。共用配置、迁移和锁文件同时只允许一个作者修改。
审查可以读取作者分支，但不同时往作者分支写代码；需要接手先明确交接。

## 第二阶段 有边界的自动化

GitHub Actions 或单一调度器按已批准的 ready 任务触发。协议如下，尚未启用：

| 阶段 | 动作 | 停止条件 |
| --- | --- | --- |
| 派工 | 校验触发者、任务依赖、当前租约，固定基准 SHA | 无负责人或依赖未完成 |
| 实现 | 单分支、单任务，限时运行，产出提交和 draft PR | 缺少业务规则、额度用完、两次修复失败 |
| 验证 | 精确提交上的测试，输出证据 | CI 失败或测试缺失 |
| 审查 | 另一代理读取准确 diff，按库存验收检查 | 审查已过期或仍有阻塞项 |
| 交接 | 状态转 review，通知仓库内负责人 | 等待合并和业务确认 |

建议初期每仓库最多一个写入任务、单次最多 30 分钟、最多 2 次修复；这是拟定预算边界，不是当前已配置的服务承诺。
禁止互相评论无限触发。使用任务 ID + 基准 SHA + 阶段作为幂等键，并配置 concurrency、超时和最大轮数。
不要让任意公开 issue/comment 都能启动付费代理；只接受白名单维护者与已批准任务。来自 PR、PDF 或网页的文本不可成为提升权限的指令。

## 认证与成本

- Codex 官方 GitHub Action 文档使用 OPENAI_API_KEY；不能假设它包含在 ChatGPT Plus 额度内。
- Claude GitHub Actions 支持文档所列 API key 或订阅 OAuth 路线，具体账号权限和额度需确认。
- Secrets 由用户在服务设置里配置，不写进仓库，不在聊天里索取密钥。
- GitHub Actions runner 用量和模型调用是不同成本。先手动完成一轮，再决定是否启用自动派工。
- GitHub 默认 GITHUB_TOKEN 产生的事件不一定继续触发所期待的后续工作流。需要显式工作流链或正确配置的 App，不能假设“机器人提交会自动唤醒另一个机器人”。

## 研究和计划更新节奏

开始任务时检查最新规则；发现实质新事实时更新对应决策；交付 PR 时同步证据与交接。
研究先读主项目官方文档、相关源码与问题记录；X 和视频提供线索，不作为库存正确性的最终依据。
不因架构偏好改写客户流程；不为新观点重写已经验证的小功能。每次架构变更明确解决什么具体问题。

## 可直接给实现代理的任务

读取 AGENTS.md、PROJECT.md、docs/DECISIONS.md、docs/HANDOFF.md 和分配给你的任务。
确认基准 SHA 和任务归属，只处理该任务；列出需要验证的假设后推进非阻塞工作。
提交实现与相关测试、更新受影响文档，给出实际执行的命令和结果，创建 draft PR。
遇未确认业务规则，记录待决项并继续独立部分；不要自动合并、发布或对真实库存过账。

## 可直接给审查代理的任务

独立审查指定 PR 的最终 SHA。根据该任务验收场景复现，不以作者总结代替检查。
优先查看数量守恒、重复操作、并发、单位、日期、原单追溯、升级恢复及真实 Windows 行为。
报告能够定位的缺陷、影响和最小复现；明确未测试的部分，不把“未发现问题”描述成商业交付保证。
